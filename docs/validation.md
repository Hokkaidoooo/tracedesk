wheel 检查先安装实际构建包，再离开源码目录启动服务。它确认导入来自安装目录、页面 HTTP 200，并真实执行“准备申请 → 确认提交 → 重复确认获得同一回执”。不能仅因源码测试通过就推断发行包完整。

浏览器测试连接真实后端，覆盖政策原文、订单与申请回执、跨客户拒绝、新会话隔离、无证据、失败后保留输入及相同 UUID 重试、评测页面，以及 390/320 px 布局和键盘操作。网络故障用例只注入失败，成功响应均来自应用服务。截图来自 CI 的实际 Chromium 页面。

## 关键反例

| 输入或故障 | 应成立的结果 |
| --- | --- |
| 同一运行两次准备同一申请 | 复用一个动作；数据库每个 run 只能有一个 action |
| 准备后又查询另一个订单 | 拒绝切换本轮订单上下文 |
| 模型携带自由的“退款已提交”回答 | 参数校验失败；业务说明只由真实状态生成 |
| 引用 ID 不存在或摘录不在原文 | 显式失败；不生成确定性回答 |
| 选择一段历史退货政策来解释当前申请 | 申请只绑定并展示实际使用的政策版本 |
| 模型响应缓慢分块、始终不断流 | 总时限仍会终止调用 |
| 工具输出超过预算 | 不发布完成状态，并取消尚未交付的申请 |
| 运行租约到期后保存回答 | 保留已有中断原因与运行 ID，首次失败和重放结果一致 |
| 确认后重放原对话请求 | 保留历史快照，HTTP 展示当前已提交状态且不再暴露确认 token |
| 两个线程同时确认 | 唯一申请、单一回执，无重复退款申请 |
| 回执写入发生异常 | 事务整体回滚，订单状态不提前改变 |

## 验证限制

外部真实模型尚未配置，当前没有模型准确率、线上流量、用户满意度或支付成功率结论。协议夹具用于检查真实 HTTP 边界，不模拟一份对外宣称的模型成绩。引用核对也不等于政策内容真实性或语义相关性证明。

固定检索集仍有未完整召回的用例，详见 [评测说明](evaluation.md)。当前测试日志包含一条来自 Starlette TestClient 的 HTTPX 弃用提示；测试已真实通过，没有通过屏蔽异常或替换成功路径消除它。运行依赖版本由 `requirements.lock` 固定。

## 本地复核

```powershell
python -m pytest -q
python -m ruff check src tests scripts
python -m ruff format --check src tests scripts
npm run typecheck --prefix web
npm run build --prefix web
python -m build
```

浏览器回归的配置位于 `web/playwright.config.ts`，会为测试单独启动后端。它不复用现有服务；重复运行应使用新的测试数据库文件，避免把已有演示申请状态当成全新初始数据。
