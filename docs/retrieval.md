# 可核对的政策检索

TraceDesk 在当前商店、当前业务日期有效的政策中寻找证据，并返回具体版本。实现仅使用 Python 标准库，不需要下载向量模型或调用外部服务。知识内容均为独立撰写的虚构电商政策，不构成真实商家的服务承诺。

## 数据与时间边界

`src/tracedesk/data/knowledge.json` 包含 17 条版本记录：16 条属于 `demo-shop`，1 条属于 `other-shop`。每条记录必须完整提供 `id`、`version`、`title`、`text`、`category`、`tenant_id`、`effective_from`、`effective_to`、`rules`。顶层 `schema_version` 为 1；未知字段、重复 JSON 键、重复 `id@version`、无效日期和重叠生效区间都会阻止加载。

生效区间使用 **[effective_from, effective_to)**。`effective_to: null` 表示没有已知结束日期。`returns@1` 从 2025-01-01 生效，到 2026-01-01 之前适用；`returns@2` 从 2026-01-01 起适用。历史缺口返回无证据，不借用下一版政策。

退款政策的唯一规则源在 `rules`：

| 版本 | window_days | allowed_statuses | excluded_categories |
| --- | ---: | --- | --- |
| returns@1 | 14 | delivered | digital、custom |
| returns@2 | 7 | delivered | digital、custom |

知识正文通过 `{window_days}`、`{allowed_statuses}`、`{excluded_categories}` 占位符读取同一份规则。加载时把状态及品类枚举转换成中文，并生成可直接引用的正文。未知占位符、属性访问和动态格式化均报错。`Document` 是冻结 dataclass；规则字典和嵌套结构只读，JSON 数组在内存中表示为 tuple，避免建索引后规则与引用文字漂移。

在检索和文档直取之前，先过滤租户和生效日期。BM25 的文档数、平均长度及词频统计也只来自过滤后的语料。因此，加入另一个商店的文档既不能进入结果，也不能改变当前商店的 BM25 分数。所有商店的 `id@version` 保持全局唯一，引用不依赖隐藏的租户前缀。

## 检索过程

三个方法共享文本规范化与证据覆盖规则；区别是排序依据。索引文本由标题与正文连接得到，不增加未公开的标题权重，也不包含过期版本、其他商店的正文或评测标签。

1. 使用 Unicode NFKC 和 `casefold` 统一全角、半角及拉丁字母大小写。
2. 将礼貌用语和常见问句词替换为词边界，在连续中文片段两端去掉语气词；中文、拉丁字母、数字和标点之间保持边界。
3. BM25 将中文片段切成相邻双字片段，单字片段单独保留，拉丁字母及数字保留完整连续词。常见低信息量双字词被剔除。不会生成跨标点的伪词，也没有隐式同义词改写。
4. n-gram 使用同一份规范化片段，分别提取 1、2、3 字符片段，计数权重为 0.2、1.0、0.5，并计算余弦相似度。片段不跨越标点或空格。
5. 应用公开的覆盖门槛，再根据方法进行排序；同分按 `source_id` 的字典序排列。

停用表达和字符权重在 `retrieval.py` 的命名常量中完整列出。该分词方式是可复核的中文词面基线，不是语言学分词器，也不等同于语义向量检索。表达与知识没有共同词面时可能漏检。

### BM25

默认 `k1=1.2`、`b=0.75`。对每个不同的查询词计算一次：

```text
idf(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))
score(d, q) = Σ idf(t) × tf(t,d) × (k1 + 1)
              / [tf(t,d) + k1 × (1 - b + b × len(d) / avglen)]
```

重复输入同一个查询词不会重复增加其 BM25 权重。词频、文档长度均依据上述词面分词。

### 字符 n-gram 与 RRF

`ngram` 方法直接以加权字符片段的余弦相似度排序。`hybrid` 对 BM25 和 n-gram 的候选排序分别计算倒数排名融合：

```text
RRF(d) = Σ 1 / (60 + rank_method(d))
```

排名从 1 开始；只在一个方法中通过门槛的文档只贡献一项。RRF 不将两种量纲不同的原始分数直接相加，也不将融合分数解释成回答正确的概率。`SearchHit` 保留两种原始分数供核查。

## 无证据与门槛

所有方法要求至少一个真实 BM25 词面命中，并要求“匹配的不同查询词数 / 不同查询词总数”达到 `min_query_coverage=0.25`。n-gram 分支另要求余弦分数达到 `min_ngram_score=0.05`。这些门槛是显式的工程策略，不是经生产数据校准的置信度。

```python
from tracedesk.retrieval import KnowledgeBase, RetrievalConfig

kb = KnowledgeBase.from_path(
    "src/tracedesk/data/knowledge.json",
    config=RetrievalConfig(min_query_coverage=0.25, min_ngram_score=0.05),
)
```

将两个门槛设为 0 可关闭质量过滤，用于对比实验；完全没有词面命中的文档仍不会被返回。空字符串、非法日期、非法租户标识、未知方法以及不合法的 `top_k` 都会抛出 `ValueError`。只有标点、只有停用表达、没有有效文档或没有匹配时返回空列表。输入长度默认不超过 2000 字符，可通过 `max_query_characters` 明确调整。

租户隔离、生效日期和数据完整性检查是检索契约的一部分，不能用调整质量门槛绕过。

## 固定合成回归与消融比较

`src/tracedesk/data/retrieval_cases.jsonl` 有 60 条固定合成查询，其中 48 条存在相关证据、12 条预期无证据。用例覆盖同义表述、过时政策前提、日期切换、无历史政策、业务能力边界、词面干扰和跨租户反例。每条用例包含查询、业务日期、租户、预期版本及类别。

`evaluate_retrieval(kb, cases_path)` 在完全相同的数据上分别运行 `bm25`、`ngram` 和 `hybrid`，保留逐条命中、分数、耗时、实际配置和 SHA-256。`dataset_sha256` 标识用例文件的原始字节，`knowledge_sha256` 标识按 `source_id` 排序、展开正文后的规范化知识 JSON；配置单独记录，避免只固定问题而遗漏知识或门槛变化。评测不会调用大模型，也不检查自然语言回答是否正确。

| 指标 | 定义 |
| --- | --- |
| queries / answerable | 查询总数 / 具有相关证据的查询数 |
| recall_at_3 | 对有证据查询计算前三条命中的相关文档比例，再对查询取平均 |
| mrr | 对有证据查询计算前三条中首个相关文档名次的倒数，未命中为 0，再取平均 |
| no_answer_accuracy | 在预期无证据的查询中，实际返回空列表的比例 |
| latency_ms_p50 | 本次串行运行检索函数的单次耗时中位数，含过滤与评分，不含加载、网络和生成 |

若某类分母为 0，对应指标为 `null`，不伪造满分。预期引用不存在、属于其他租户或在查询日期未生效时，评测直接报错。

这是已知知识上的固定合成回归，不是盲测、公开基准、真实客户满意度或线上模型准确率。固定用例可以发现代码退化，但不足以证明对新表达的泛化能力。不能仅因融合方法名称更复杂就宣称优于 BM25；应比较同一次评测的实测数据和失败案例。

## 复核入口

```console
python -m pytest tests/test_retrieval.py -q
```

测试覆盖手算 BM25 与余弦分数、RRF 排名、稳定平分、时间边界、租户对统计量的隔离、模板与规则一致性、坏配置拒绝及评测分母。最终评测数值由实际执行生成，本文不固化一份可能与代码脱节的成绩单。

当前限制包括：中文切片可能拆开术语，词面覆盖门槛可能拒绝有用的口语提问，静态知识不能证明实时物流或支付状态，毫秒级耗时会随机器和进程负载变化。扩大样本、由独立标注者构建未参与实现的评测集，以及引入可复现的语义检索对照，均需要后续单独验证。
