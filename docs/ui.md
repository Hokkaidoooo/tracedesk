# 客服工作台与资料库

TraceDesk 提供“对话”“资料库”“评测”三个视图，共用当前演示会话。对话用于售后办理与资料研究，资料库管理原件和已发布版本，引用区展示回答依据与实际执行记录。

## 使用资料库

1. 选择演示身份，上传 UTF-8 TXT、Markdown 或已配置解析器的 PDF。标题相同的新原件形成新版本；重复原件返回已有版本。
2. 查看文档状态。解析失败保留原件与具体错误，修正服务后可点击“重试解析”；下载原件可核对实际文件。
3. 选择需要的词面、语义或关系图索引，点击“构建并发布”。失败仍可查看旧发布版本。
4. 在“检索原文”中选择已发布快照和实际可用的方法，输入问题后展开来源。
5. 已启用研究时，可点击“用此版本研究”，把当前明确选择的资料快照带入对话。

“加载示例资料”提供原创文档和有出处的人工关系。语义、自动关系抽取或研究未启用时，对应选项按服务能力禁用。本地图示例可以离线使用，不能作为模型抽取成绩。

当前版本的 `method_status` 提供索引与配置不匹配的原因。界面合并同一原因的提示；普通未配置能力只保持禁用，不反复弹出警告。外部服务在真正请求时失败，仍显示返回的错误。

## 对话与研究

“售后办理”查询正式政策、核对订单并准备售后申请。确认卡片展示订单、金额、原因与有效期，提交结果以服务返回的回执为准。

“资料研究”使用固定的已发布快照。“协作研究”对应 `multi`，“单角色研究”对应 `single`；后者为单研究者加公共核验角色，两种模式都会核验证据。首次选择使用服务返回的默认模式，用户明确选择后，刷新资料不会覆盖这一选择。

研究的 `partially_supported` 显示为“部分结论有依据”，`insufficient_evidence` 显示为“证据不足”。执行记录中的角色与步骤来自服务端事件，界面不生成模拟角色、占位进度、token 用量或思维链。

发送失败后保留草稿和请求 UUID。研究重试同时保留消息、模式、快照和 UUID；修改其中任一请求参数会生成新请求。旧请求不会因为发布了新资料就自动使用新快照。

## 引用与原件

引用使用明确的联合类型：

| 引用 | 展示内容 |
| --- | --- |
| 正式政策 | 原文、政策版本、生效与失效日期、读取方式或检索分值 |
| 上传文档 / 研究 | 原文、文档版本、知识快照、原件 SHA-256、真实页码、内容类型、检索方法、关系路径 |
| 研究结论 | 文档来源加 `claim_id`，对应具体受核验结论 |

没有分页的 TXT、Markdown 与 MinerU CLI 输出显示“不提供页码”，不推测页号或生效日期。检索分值用于排序，不表示回答正确率。

原件下载通过带当前 Bearer token 的请求读取，校对响应的 `X-Source-SHA256` 后使用临时 Blob URL 下载。token 不进入下载 URL。文件内容、原文 HTML、标题、模型回答和错误文本均使用 `textContent` 展示，不作为页面 HTML 执行。

## 会话与异步状态

会话 token 和确认凭证只保留在页面内存，不写入浏览器持久存储、页面文本或 URL。刷新页面会创建新会话，不重置后端订单或资料。

会话列表只展示当前演示客户的会话；切回原客户后可以重新读取其历史。两位默认演示客户属于同一商店，因此商店资料可以共享，但查询结果和当前会话身份必须重新读取。

切换客户或会话时清空资料视图状态、取消未完成的资料请求，并使用会话代次检查迟到响应。旧响应不能覆盖新身份的目录、引用或检索结果。服务端仍独立执行商店与会话校验，前端状态清理不代替授权。

所有 JSON、原始字节上传和文件下载共用同一传输与错误处理。页面不另行实现退款资格、订单金额、租户权限或检索就绪判断。

## 键盘与小屏

消息框支持 Enter 发送、Shift + Enter 换行，并识别输入法组合输入。资料表单有明确标签，引用使用原生 `details`；详情页签支持方向键和 Home / End，操作结果通过 `aria-live` 通知。

宽屏对话同时展示会话、答复和证据。1090 px 以下可切换对话与证据，700 px 以下增加会话分区并将导航置顶。资料库在小屏改为纵向卡片，表单和原文在各自区域内显示；最小目标宽度为 320 px。

减少动态效果偏好通过 `prefers-reduced-motion` 生效。

## 前端开发

先从仓库根目录启动后端，再运行：

```powershell
Set-Location .\web
npm ci
npm run dev
```

页面位于 `http://127.0.0.1:5173`，`/api` 默认代理到 `http://127.0.0.1:8765`。自定义后端地址可设置 `TRACEDESK_DEV_API_URL`。界面使用 TypeScript、原生 DOM 和本地资源，不依赖外部 CDN。

```powershell
npm run typecheck
npm run build
npm run test:e2e
```

构建写入 `src/tracedesk/web`，源文件位于 `web`。包内目录只保留构建产物。浏览器测试需要相应浏览器可执行文件；默认测试通过后端读取已构建界面。

| 模块 | 职责 |
| --- | --- |
| `api.ts` | 唯一传输、Bearer 身份、解码与售后接口 |
| `knowledge-api.ts` | 共用传输的文档、发布、检索与原件接口 |
| `main.ts` | 会话、研究模式、固定快照、草稿与重试 |
| `knowledge-view.ts` | 资料操作、能力状态、历史版本与异步作用域 |
| `components.ts` | 政策和文档引用、执行事件、申请与评测的安全渲染 |
| `dom.ts / style.css` | 元素与格式化、布局、状态与键盘焦点 |

## 验证入口

`web/e2e/workspace.spec.ts` 覆盖政策、订单、确认回执、权限、会话切换、请求回放和评测页面。`web/e2e/knowledge.spec.ts` 覆盖真实后端上传、发布、历史查询、授权下载、失败重试、资料图检索和小屏布局。

研究界面另有明确标注的 HTTP 协议夹具，验证默认模式、用户选择、固定快照、重试参数和研究引用；它不代表真实模型研究质量。截图与整体验收结果以[v0.2 验证记录](validation-v0.2.md)为准。

可通过 `TRACEDESK_E2E_OUTPUT_DIR`、`TRACEDESK_E2E_DATABASE`、`TRACEDESK_E2E_PYTHON`、`TRACEDESK_E2E_API_PORT` 指定独立测试目录、数据库与解释器。设置 `TRACEDESK_E2E_VITE=1` 可测试源码界面，`TRACEDESK_E2E_WEB_PORT` 控制该页面端口；默认使用已构建产物。测试不应指向正在使用的业务数据库。
